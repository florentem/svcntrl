# Вопросы и концептуальные решения для следующего спринта

В процессе полного ревью и исправления багов мода **svcntrl** были выявлены некоторые концептуальные моменты, требующие обсуждения перед их изменением, чтобы не нарушить задуманную архитектуру.

## 1. Синхронное удаление файлов авто-снапшотов (Project.java)
В методе `trimAutoSnapshots` старые файлы авто-сохранений удаляются с помощью `Files.deleteIfExists(...)` прямо в основном потоке (Main Server Thread). 
* **Проблема:** Хотя количество снапшотов ограничено 10-ю, удаление файлов на медленных дисках может вызывать микро-лаги сервера (TPS drop).
* **Вопрос:** Стоит ли перенести эту логику в асинхронный поток (через `CompletableFuture.runAsync`), по аналогии с созданием снапшотов?

## 2. Экспорт на tmpfiles.org (ExportManager.java)
Сейчас публичный экспорт (для серверов) жёстко завязан на сторонний бесплатный сервис `tmpfiles.org`.
* **Проблема:** Сервис может быть недоступен, удалить файлы раньше времени или изменить API.
* **Вопрос:** Стоит ли добавить возможность настройки кастомных S3-совместимых хранилищ (или WebDAV/FTP) через конфиг для надёжного экспорта схем?

## 3. Загрузка чанков при восстановлении (AreaSerializer.java)
Процесс восстановления (`RestoreTask`) использует тайм-слайсинг для защиты TPS, но при вызове `world.getWorldChunk(...)` непрогруженные чанки могут загружаться синхронно в основном потоке.
* **Проблема:** Если восстанавливается огромный регион (миллионы блоков), это может привести к каскадной загрузке чанков и лагам, несмотря на лимит времени.
* **Вопрос:** Стоит ли внедрить систему "Chunk Tickets" (как в vanilla), чтобы предварительно асинхронно прогружать нужные чанки перед началом восстановления конкретного сегмента?

## 4. Локализация сообщений (I18n)
Почти все сообщения (ошибки, инфо, прогресс в Actionbar/Chat) написаны хардкодом на английском языке через `Text.literal(...)`.
* **Вопрос:** Планируется ли поддержка нескольких языков (через языковые файлы `.json` и `Text.translatable()`)? Если да, то стоит вынести все строки в ресурсы в следующем спринте.
